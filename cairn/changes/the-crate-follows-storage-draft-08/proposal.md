# The crate follows storage-draft-08, sync-draft-07 and search-draft-08

## Why

pimdir's release audit of 2026-10-31 (pimdir cairn/changes/audit-2026-10-31, eight log entries dated 2026-10-31, commit d671bbd on pimdir's branch audit-2026-10-31, not tagged, not on master) moved the parts to storage-draft-08, sync-draft-07, search-draft-08 and gtd-draft-03. This crate follows storage-draft-07, sync-draft-06 and search-draft-07 (fb71740; HEAD ec6603b, pushed, clean).

pimdir's freeze gate is the reference implementation passing every check and vector at the draft to be released, so storage-v1.0.0 waits on this change. Against a sibling pimdir checkout at d671bbd the vector suites already fail today: sync cases and queries.json are at `v` 2, summaries.json holds 53 cases, objects.json is at `v` 2 and names one shard level.

Drafts are exact: a draft-08 program refuses a draft-07 store, never reconciling it. Every store this crate or its consumers wrote (neverest, himalaya, the Android app) is reinstalled at the switch; nothing migrates. That deletes most of the crate's reconciliation code rather than extending it.

## Decisions

The user took every recommended answer on 2026-10-31.

1. **Pin.** Vendor from d671bbd now, recorded in a new spec/REVISION, and re-vendor if pimdir moves before its tags. Waiting for the tags would serialise the two repositories for nothing: spec_drift compares content, so a squash of the branch onto master keeps the pin valid.
2. **Vendor the vectors.** spec/ takes vectors/ and payloads/ (1.4 MB and 48 KB) beside migrations/ and queries/, checked against vectors/manifest.json; every suite reads spec/ and none skips, which answers the pimdir follower "its spec suites fail rather than skip in CI without the spec checkout". The package keeps excluding them. The alternative, CI checking out pimdir at the pin, keeps the skip locally and adds a CI dependency.
3. **A pending-vector list.** tests/pending_vectors.txt names each vector case expected to fail, with the phase that fixes it; a runner fails on an unlisted failure and on a listed pass, so the list only shrinks and CI stays green between phases. Release needs it empty. This is pimdir's checks/waivers.txt applied to vectors.
4. **Refusal errors.** One `PimdirError::Version` (code `store-version`) for a store of another draft, one lacking `format_version` (any draft before 08) and a release; `PimdirError::SyncVersion` (`sync-version`) for another draft's sync state; `PimdirError::IndexVersion` (`index-version`) for an index of another shape or a later version. `PimdirError::Shape` (`store-shape`) and the `NotCurrent::Shape` and `Stale` paths that only reconciliation needed go. `Foreign` (not a pimdir store) stays. Codes are a public contract (machine-output-contract), so this lands once, in the breaking release.
5. **Every owner decodes every WHATWG label.** A.1 decodes an encoded word in any label of the WHATWG Encoding Standard and keeps an unknown one literal; the default build reads unknown labels as UTF-8 and `iso-8859-1` and `us-ascii` as Latin-1 (WHATWG reads them as windows-1252). `client` enables `charset-tables` (encoding_rs), and a build without it keeps a label it has no table for literal, a deviation stated in summaries.md.
6. **One zone database.** The derivation resolves a `TZID` its resource does not define through `jiff` with its bundled tzdb, the database ical-rs's `tzdb` feature already brings to the index, as a direct no_std `alloc` dependency. The sort key and the occurrences then read one database version, and the no_std build conforms too.
7. **`PimdirLoadScope` becomes `PimdirLoadSelection`** (STORAGE §2 now calls `All`, `Handles` and `Links` a selection, a scope being the date window). Breaking, so it rides this release or never; it touches what a-delta-loads-what-it-names reshapes, so that change rebases on it.
8. **An erase verb.** `PimdirClient::erase` and `pimdir item erase` run STORAGE §11.5 in order: the purge (or `delete_unbound_item`), the collector, the index refresh with its thread prune, `optimize_text`, then `wal_checkpoint(TRUNCATE)` on both files.
9. **Link-free opens through rustix**, already in the tree through fs4, as a direct dependency for `O_NOFOLLOW` on Unix; Windows opens with `FILE_FLAG_OPEN_REPARSE_POINT` through std.

## Phases

One agent batch per phase, in order, each landing with its log entry, its capability folds and its CHANGELOG lines, every non-vector suite green and the pending list shorter. Commits are the user's, one per phase or one at the end.

0. **Vendored vectors, nothing else moves** (S). spec/ takes vectors/ at 9606b43, the revision the crate passes today; the suites read spec/ and never skip; spec_drift compares with the pinned revision through `git show` when a pimdir checkout exists, so a sibling on another branch no longer breaks it. Lands alone and green, so the rest starts from suites that cannot skip.
1. **The store opens storage-draft-08** (L). Re-vendor all of spec/ at d671bbd; build.rs generates the new statements; the pending list is seeded from the first run. Then: the exact marker on every profile and `PimdirError::Version`; reconciliation deleted with its tests; BLAKE3 alone (`init_store_meta` without `:hash_algo`); the three compatibility versions read; `store_id` and `incarnation` read, `raise_incarnation` exposed; `set_derivation` setting rather than raising; `sync_version` written by the first sync write and checked; `synchronous = FULL`, `secure_delete = ON` on every writing connection, a busy timeout for readers and producers, `fullfsync` on macOS; the re-signed statements bound (`_by_link`, `load_addresses_by_collection`, `seq_for_link_any` with `:collection`, `list_unstamped_bindings` with `:narrowed` and `:enumerated` at 0 until phase 5, `count_mail_by_day` in minutes, `list_address_placements` paged); the index statements bound as re-signed (`init_index_meta`, `load_index_meta`, `set_index_cursor` without `store_reconciled`, `coverage`'s slot, `placements_gone`), the purge count alone reconciling keys.
2. **The blob store** (M). One shard level; `PimdirHash` parsed and checked (52 characters of `a-z2-7`) before any path; the no-replace write by `hard_link` then `remove_file` of the temporary, an existing name kept; no link followed under objects/; the collector unlinking only a regular, well-formed file in its own shard; quarantine/ for a body failing its name, moved by the owner under the exclusive staging lock; verification before a body is served, parsed, pushed or copied, a range read verifying the whole file through its descriptor first; the drain reading `queue.object_hash` and parking a payload whose `object` differs; objects.json `v` 2.
3. **Annex A revision 3** (L). The A.1 parses as the identity-and-derivations entry lists io-pimdir's differences; decisions 5 and 6; A.3's offset before a gap and its 1,000,000-period rule bound; the 10,000-entity walk and 1,000 stand-ins (shared by the derivation and the extraction); a card's `KIND` and `ORG`, an event's organizer and attendees, a journal; `DERIVATION` 3 and the re-derivation of held mail and tasks through `list_held_mail` and `list_held_tasks` when the store records an earlier revision; recording our revision when a later owner wrote. summaries.json passes, 53 cases.
4. **Payloads and capabilities** (M). 5. **The engine on sync-draft-07** (L, the riskiest). `PimdirRemoteSnapshot` gains `narrowed` and `enumerated`; the narrowed absence rule through `list_unstamped_bindings`; the empty-listing park for rounds and rekeys; a mutable revive at `Meta` keeping the retained body over the reviving handle, `Overruled`; the mail agreement against every held row, a retained one on size too; a divergence over an unread body recorded `Manual` whatever the policy, then settled by the upgrade or the fill; `PreferLocal` keeping the body it pushes over in a write committed before the push; the upgrade settling a binding conflict by the source's policy; decision 7; the runner reading sync vectors at `v` 2 (`narrowed`, `enumerated`, `carries`). pimdir predicts failures at vectors 15, 106, 107, 108, 112 to 117, and possibly the rewritten 04, 16 and 61.

7. **Security, erasure, conformance** (M). Directories `0700` and files `0600` (pimdir.db, index.db, the locks, `-wal`, `-shm`); lock files opened without following a link (decision 9); a store from elsewhere opened with `trusted_schema = OFF` and `SQLITE_DBCONFIG_DEFENSIVE`; export paths neutralised (separators, `.`, `..`, NUL, control and bidirectional characters); error text scrubbed of credentials; decision 8; README states `storage-draft-08 owner, sync-draft-07 engine, search-draft-08 indexer (canonical) and query client`; the pending list empty; CHANGELOG read as a net diff.

## Not in this change

- The followers of this one: neverest's connectors stating `narrowed` and `enumerated` (IMAP `SENTSINCE` and `UID SEARCH ALL`, JMAP `after` and `Email/query` by mailbox, Graph `receivedDateTime` and its ids, Gmail `after:`) and keeping what `PreferLocal` pushes over; himalaya and pimalaya-cli for the API breaks; the Android app (its own platform-sqlite change: BLAKE3, one shard level, `queue.object_hash`, the rename, its index shape); pimdir's CI running this crate's vector runner at a pinned revision.
- pimdir's open items: S10 (a local `Edit` over a binding whose base names no body) and the absence-propagation guard stay as the engine does them today; the pending bit and the purge log come after v1.
- This crate's own drafts. derivation-before-the-write touches phase 3's code and rebases after it; a-delta-loads-what-it-names rebases on decision 7; an-owner-write-checks-its-fence waits for pimdir to state the fence; the others are independent.
- Version bumps and publishing: CHANGELOG under Unreleased only.

## Risks

- Phase 5 changes push decisions; a wrong reading pushes over a server body. The sync vectors are the oracle, and the engine's property suites (tests/engine/) must pass unchanged in what they assert, any change to an assertion named in the log.
- Phase 1 deletes reconciliation that consumers' stores relied on. Every consumer reinstalls; the CHANGELOG says so first, and `pimdir check` names the refusal plainly.
- The pin moves if pimdir changes before tagging; decision 1 and spec_drift make that a re-vendor, not a silent drift.
