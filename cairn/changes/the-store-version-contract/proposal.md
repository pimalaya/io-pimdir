# The store version contract

## Why

pimdir spec edit 1 (plan, 2026-10-30) gives the store a version contract before `storage-v1.0.0`: after v1, 0001 never changes; every change is a migration bumping `user_version` and `store_meta.version` through a canonical statement; an implementation MUST refuse a store above its version, never reconcile nor rebuild it; reconcile only normalises version 1 stores, before migrations; a migration preserves every table. The frozen schema is `user_version` 1 (draft stores are 1 too).

io-pimdir is out of step with it (report-io-pimdir.md, blocker 2; review-io-pimdir.md, B2, S2, S3, S4):

- reconcile drops the tables and columns it does not know (src/client/schema.rs:173-211) at an unchanged `user_version` 1, so an older binary deletes a newer one's data;
- migrations run before reconcile (schema.rs:60-87), so a 0002 would meet a draft-shaped store;
- the version bump is ad hoc SQL (schema.rs:76), and the backfills write outside queries/ (schema.rs:281, :323);
- `store_meta.format` is never checked, so a foreign `pimdir.db` gets its tables dropped;
- `open_with_hash` reconciles before refusing a mismatched algorithm (client.rs:224-225);
- no fixture of a store an earlier release wrote, no migration test.

## What

- The owner open, in order: refuse a database that is not a pimdir store (`store_meta.format`, or a version-0 database already holding tables); refuse a store above this crate's version (`PimdirError::Version`, its message saying to upgrade); reconcile a version 1 store to the frozen 0001 only, before any migration; run each migration above, bumping both stamps through the canonical statement in its transaction. What 0001 lacks is dropped at version 1 only, as STORAGE §6 step 3 says; a newer owner adds through a migration, which this crate refuses.
- The hash algorithm checked before anything is written.
- Readers and producers: the rule pimdir gives for an older store.
- Annex A's derivation revision in `store_meta`, as the spec states it.
- Fixtures: stores generated by the io-pimdir v0.5.1 and v0.7.0 tags (and 0.8.0, untagged, from its release commit 3b9154a), checked in, each opened by the owner and read back intact; a synthetic 0002 proving the runner, the bump and the table preservation.
- The docs the contract rewrites: cairn/spec/store.md "Schema version" and "Open reconciles against the canonical text", src/client/schema.rs, tests/stale_store.rs.
- The CLI owner verbs reviewed again against the contract (only-the-sync-engine-migrates moved them to `open_current`).

Depends on pimdir storage-draft-05 (spec edit 1). The "delete the store" advice is errors-carry-a-stable-code's.
