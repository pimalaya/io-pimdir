# The engine on the revised SYNC part

The standard's SYNC part was revised the same day and fourteen vectors joined the ten the engine reproduced; all twenty-four reproduce now, the harness comparing every field a push carries and running a `mutate` verb. Nine divergences went, each in the capability that owns it: the change key folds a flag count in decimal ASCII as SYNC §4 fixes (sync); a tombstone's destination is what the store derives from the pending create the same source holds elsewhere, the hub asking its resolver for tombstones too (sync, hub); a fetched hint a pending create holds lands the create with a `Superseded` drop instead of minting (upgrade); an accepted content push rebases the row the flag merge last wrote, one pending map the flag axis refreshes replacing four (sync); a rekey meeting a revision its base never held carries a pull, a conflict over a local edit, or a revived tombstone, never a base at it, and resolves the new spine in chunks of `FETCH_CHUNK` (rekey); a re-listed probe with its stored flags rewrites nothing and a probe an enumeration no longer lists is dropped like any member (sync); a rejection counts for a pushed handle only (sync); a tombstone's known flags ride along and a body-less item is no divergence for a source whose base holds a body, a pull lowering the shared level with the body it drops (hub); an edit on a pending create drops its origin (mutate). `PimdirDeletePolicy::Auto` is the default the std client resolves from the binding count, and every coroutine names its states in the present tense and refuses every resume after completion (coroutine).

The property suites can fail now: no verb runs under `let _ =`, an erroring sync is not a report, raced deletes assert edit-beats-delete across sources, the identity model asserts the server and the replica hold the same members, and cold moves land exactly one copy over a relocating remote and over one that rejects. The oversized unit test modules moved beside their modules and the join out of the sync.
