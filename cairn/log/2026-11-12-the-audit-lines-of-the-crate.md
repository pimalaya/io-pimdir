# The audit lines of the crate

The lines of the audit of 2026-11-12 (pimdir cairn/changes/audit-2026-11-12, proposal.md and its ledger tasks.md) that are the crate's alone and wait for nothing in the standard's next draft: T1, T2, T5, T6, Y6, S1, S3, V2's judgement, and T3's test. spec/ is not re-vendored and no statement text moved; the lines that follow storage-draft-10 and sync-draft-10 land with the pass that makes the crate follow them.

## What landed

- **T2, the collector's exclusion.** Three writers escaped it. (a) `PimdirStore::put_item` stages its body before `BEGIN IMMEDIATE` and holds the process's writer lock shared from the blob through the commit, as `PimdirSourceStore::write` does; it wrote the blob inside its transaction under no share. A name held by a failing file is set aside through `PimdirStore::quarantine`, the share let go for the move, once. `collection_sources` is read before the staging too, so a refused put stages nothing. (b) The in-flight guard is read after the locks: `collect_garbage` takes the staging lock, then the writer lock exclusively, then reads the count; `collect_before` and `release_before` take the writer lock exclusively, which they did not take, then read it. `PimdirLock::running` raises the count under the writer lock held shared, so a verb starting waits a collection out and none starts behind a guard already read. A producer inside its window is now reported (`Staging`) before a verb in flight is. (c) A producer's enqueue naming a body it did not stage (not in its window as a body staged whole and unpinned, the window not holding a stream) takes the staging lock shared before its transaction and verifies the file against its name under it: absent is `PimdirError::Io` `NotFound`, failing its name the `InvalidData` a write meeting it answers; nothing is queued and no object row recreated. An append that fails closes a window it alone opened.
- **An owner's stage holds what its writes hold.** Found while making T1 safe: `PimdirBlobStage::stage_body` on an owner's stage wrote under no share, and a `PimdirBlobWriter` an owner opened outside a verb was invisible to the collector, which T1 would have made unlink a live temporary. The first now holds the writer lock shared across its write; the second counts as a verb in flight until it is committed or dropped (`PimdirLock::streaming`), so a collection beside it is refused as `InFlight` where it ran before.
- **T1, the temporary a killed writer left.** Under its locks `collect_garbage` unlinks every period-prefixed regular file, read by `lstat`, in objects/ and its shard directories, and counts them in `PimdirGcReport::temporaries`, their bytes in `bytes` when the file was the last name of its content (`nlink`, on Unix). A link and any other name stay in `strays`. `pimdir gc` prints and answers the count (`temporaries`), and `pimdir check`, which still lists a temporary as a stray, names `pimdir gc` for it. The crate leads the standard here: the vendored STORAGE §5 still says a temporary is left alone.
- **T5, the directory flushes.** The shard directory is flushed on both paths keeping a held name (the write skipped, and the link meeting a name made meanwhile); a batch flushes each distinct shard once and objects/ once (`PimdirBlobs::stage` over `put`), where it flushed once per body; the collector flushes every directory it unlinked in, then objects/, before it answers, so before an erase does.
- **T6, the pages given back.** `PRAGMA journal_size_limit` on every connection, 4 MiB: just above the 1,000 pages of 4 KiB the default automatic checkpoint lets a WAL reach, so the steady state is reused and never truncated and only what a large batch grew goes back; SQLite's Android default of 1 MiB would truncate and regrow the file every checkpoint cycle here. `PRAGMA incremental_vacuum(4096)` after `purge_retained_before`, `collect_before`, `release_before` and `collect_garbage` when rows went: 16 MiB at most per call, each moved page written to the WAL once. A failure is logged, the rows being committed. The pragma answers one row per page and frees no more than it is stepped for: run through `execute_batch`, which steps once, it freed one page, which the test caught.
- **Y6.** `PimdirHub::bound_placement` compares flag sets only when both are known (SYNC §3 rule 4); it compared them as values, so an unknown base or an unknown held set read `Dirty`. Every vector passes unchanged.
- **S3.** A re-expansion that cannot read the body of an item keeps its occurrences and emits `PutMissing` where it emitted an empty `ReplaceOccurrences`. Recording alone would not have re-expanded: the object row is there, so the fold of the recorded rows planned no body and `emit` forgot the record. The fold of `load_missing_items` therefore expands every calendar row holding a body (`Fold::plan`), `emit` replaces the occurrences when the expansion read the body, keeps the record when it did not, keeping the occurrences of that same body, and leaves the record alone for a calendar feed row the page did not expand.
- **S1.** src/search/html.rs: a tag separates the text on its sides unless its first word is one of 36 inline elements (`INLINE`, listed in cairn/spec/search.md); a comment separates nothing. The tag's name is read whatever attributes follow. The push at `<` takes its space by the rule of the other pushes and clears the line-start mark, which it left set: `a<br>b<i>c</i> d` read `a\nbcd`. No change to the standard.
- **V2.** `version::PimdirStoreVersion::opens`, I/O-free, with `PimdirProfile`, `PimdirFormat`, `PimdirProgram` and `PimdirVersionRefusal`: the draft rule and the released one of STORAGE §4.2. `schema::check` takes the opener's profile and asks it for its marker test, as a draft program, so every open refuses what it refused, in the same order.
- **T3.** tests/store_version.rs `a_restored_copy_raises_its_incarnation` asserts "above both, and moved" and no exact value; `raise_incarnation`'s text is the vendored one, untouched.

## What a release still needs (V2)

The judgement is run for the draft alone. Before a released build opens a later store through it: `schema::check` compares the whole schema with 0001_init.sql's text and asks `user_version` to be `sql::VERSION`, where a released reader or producer will compare the schema text only up to its own version and read the store as that version defines it; `Unknown`, `Read` and `Produce` need a `PimdirError` variant and a stable code each; an owner opening a lower version needs the migration runner; and the standard has to say whether the major a marker names must agree with `version`, which the judgement does not compare.

## Open

- The standard's half of T1, T2 and T5 (a sentence each in STORAGE §5 and §8), S3 (SEARCH §4, §7) and V2 (§4.2, §18) is pimdir's, in the same audit; spec/ follows at the next re-vendor.
- A queued enqueue naming an absent body answers an I/O error by its kind; whether it deserves a code of its own is the standard's to say (STORAGE §5 has a producer "fail its write, reporting the name").
- The fold wipes the occurrences of a calendar row whose new body cannot be read and whose placement was expanded from another body, as before: the old body's occurrences are not the item's any more. It now records the row missing where it forgot it.
- `<style type="text/css">` and any other hidden element carrying attributes is still not recognised as hidden by the HTML reduction, which matches `head`, `style`, `script` and `template` only on a tag of one word (mail-parser's rule): its text is indexed. Not S1's; left.
- T3's statement text, T4, T7 and C4 are not this entry's.
