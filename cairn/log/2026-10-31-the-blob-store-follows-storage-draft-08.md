# The blob store follows storage-draft-08

Phase 2 of the-crate-follows-storage-draft-08, after pimdir's 2026-10-31-the-blob-store (STORAGE §3, §5, §7, §8, §15.3, §18; GUIDE §4). The blob tree moves to one shard level, a name is checked before it becomes a path, a write never replaces a file, no link is followed under objects/, the collector unlinks only a body in its own shard, a body failing its name is moved into quarantine/ by the owner and fetched again, and the drain reads a queued body from its row. The 13 objects.json cases pass and left tests/pending_vectors.txt.

## What landed

- **One shard level** (STORAGE §5): src/client/blobs.rs lays a body at `objects/<hash[0:2]>/<hash>`; `pimdir export` lays its dump the same way through `PimdirBlobs::path`, its manifest at `format_version` 3.
- **A name before a path** (STORAGE §5): `PimdirHash::is_name` (52 characters of `a-z2-7`, `PimdirHash::LEN`) and `object::is_name` for a directory entry. The check lives in the blob store rather than in the type: `PimdirHash` keeps its public `String` field, since the I/O-free engine and its unit tests name bodies by any string (`h1`, `body`) and nothing there builds a path; every path is built by `PimdirBlobs::locate`, which refuses a malformed name as `ErrorKind::InvalidInput` before joining it, so `path` (now `io::Result<PathBuf>`), `get`, `reader`, `verified`, the write and the quarantine all check. The collector reads an entry as a body only under a well-formed name. The schema's `CHECK` already holds every column naming a body to the shape.
- **No link followed** (STORAGE §5, decision 9): rustix 1 (`fs`, `std`) a direct dependency on Unix under `client`; a body opens by `openat(CWD, shard, O_RDONLY | O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC)` then `openat(dirfd, name, O_RDONLY | O_NOFOLLOW | O_CLOEXEC)`, and on other platforms each is read by `symlink_metadata` before `File::open`. A link, or anything that is no regular file, at the shard or the body is no body (`PimdirBlobOpen::Stray`): every read answers it missing, a write refuses a shard that is no directory, the owner quarantines it.
- **The no-replace write** (STORAGE §5): a whole body goes to `.<name>.<pid>-<seq>-<nanos>.tmp` in its shard, created exclusively, `sync_all`, then `std::fs::hard_link` onto the name and `remove_file` of the temporary; `AlreadyExists` keeps what holds the name and discards the temporary, any other failure fails the write. A streamed body (`PimdirBlobWriter`) does the same from `.tmp-<pid>-<seq>-<nanos>` in objects/. The shard is made sure of first (`create_dir`, then `symlink_metadata` is a directory), so no name is looked up through a link where a shard belongs; the shard directory is synced after the link, objects/ too when the shard was created (std's `sync_all` is `F_FULLFSYNC` on macOS; Windows has no directory flush, `sync_dir` does nothing there, where the old code failed opening a directory).
- **The collector** (STORAGE §5): `PimdirBlobs::scan` answers `PimdirBlobScan { files, strays }` from `DirEntry::file_type` (the entry's own type, never a link's target): a body is a regular file whose well-formed name begins with its shard's name, the shard a directory named by two characters of the alphabet; anything else is a `PimdirBlobStray` (`Temporary`, `Link`, `Foreign`). `collect_garbage` unlinks only unreferenced `files` and reports the strays in `PimdirGcReport::strays` (no longer `Copy`); `pimdir check` lists them (`strays`) and the files of quarantine/ (`quarantined`), both counted as problems, and `pimdir gc` counts the strays. quarantine/ is never walked. `PimdirBlobs::files` is gone.
- **Verification before use** (STORAGE §7): `get` reads whole through one descriptor and checks; the new `verified` answers the file read whole and checked through its descriptor, rewound, for a range or a copy; `reader` fails the read reaching the stated length or the end, as before. Each read path: the reader's API, the search index's refresh and item reads, the capability gate and the drain's derivation through `get`; the attachment walk through `reader`, now reading past where the walk stops to the end before anything walked is recorded (the walk stopped at the last boundary and recorded stand-ins of a body it never checked); the verification before a push (`PimdirSourceStore::verify`), the upgrade's verification and the dedup lookup (`lookup_objects`) through `PimdirStore::check_body`, a streamed check that quarantines; `pimdir item export` and `pimdir export` through `verified` (the export streamed through `reader`, so a body longer than one copy buffer was served in part before its read failed). The engine's connectors stream a push through `reader`, failing at its end.
- **Quarantine** (STORAGE §3, §7): `PimdirStore::quarantine(hash)` takes the staging lock exclusively (a producer holding it leaves the move to the next read) and the process's writer lock exclusively (`collecting`), checks again, then moves the failing file, or the link at the body or its shard, to `quarantine/<name>.<pid>-<seq>-<nanos>` by `rename` to a name checked free under those locks, syncing quarantine/, the directory it left and the store directory when quarantine/ was created; it logs the move at `warn`. It never unlinks. Owners move on reads made outside a write transaction, since the writer lock is not reentrant: the drain after rolling back a row whose body failed (`queued_body` now fails `InvalidData` for a body failing its name, `NotFound` for a missing one, both retried then parked as an-unreadable-body-is-retried-then-parked set up), `verify`, `lookup_objects` and, through them, the upgrade. `discard_unverified`, which unlinked, is gone. A reader and a producer move nothing.
- **Fetched again** (STORAGE §7, SYNC §6): a `Full` upgrade (src/upgrade.rs) first yields `PimdirYield::WantsVerify` with the bodies its requested placements hold at `Full`, unconflicted and with no staged edit (`held_bodies`), and treats those the storage leaves out as missing: `pending_handles` revisits them and a dedup hit naming one fetches instead. The Loading arm's tail moved into `raise`. `lookup_objects` answers only sound bodies, so a placement at `Meta` is never linked onto a failing one either.
- **The queued body** (STORAGE §15.3): `apply_queued` parks, after its claim and before its gate, a row whose `add` or `update` payload names an `object` other than `queue.object_hash`, the column `NULL` included, naming both (`restated`); the body is then read through the column's value.
- **objects.json `v` 2**: tests/objects.rs's 13 cases pass at one shard level and left tests/pending_vectors.txt, now 40 cases (phases 3 to 6).
- **Tests**, each failing with its rule removed on a copy of the finished tree in the scratchpad (tests built with `--manifest-path` and their own target directory, the rule reverted by one edit, then restored): tests/blob_store.rs `a_write_never_replaces_what_holds_the_name` (Unix; `rename` and `path.exists()` in place of `hard_link` and `symlink_metadata`), `a_link_as_a_blob_is_not_followed` and `a_link_as_a_shard_is_not_followed` (Unix; `File::open` in place of the `openat` pair), `a_malformed_name_is_refused_before_a_path_is_built` (the name check reduced to a length of two), `the_collector_leaves_what_is_no_body_and_reports_it` (the well-formed name and shard prefix dropped), `the_collector_leaves_a_link` (Unix; `fs::metadata` following the entry), `the_owner_quarantines_a_corrupt_body_and_a_reader_does_not` and `the_verification_before_a_push_quarantines_a_corrupt_body` (`remove_file` in place of the move; the second also with `verify` checking without quarantining), `a_payload_restating_another_body_parks` (the `restated` park removed: the drain applied the payload's body), `an_export_serves_no_byte_of_a_corrupt_body` (feature `cli`; `reader` in place of `verified`: its first bytes were printed before the read failed); `a_body_lives_one_shard_level_down`; tests/attachments.rs `a_body_failing_its_name_past_the_walk_stands_for_nothing` (the read to the end removed); tests/engine/quarantine.rs `a_full_item_whose_body_fails_its_name_is_fetched_again` (`held_bodies` answering none) and `a_dedup_never_links_onto_a_body_failing_its_name` (`lookup_objects` answering a failing body); src/object.rs `a_name_is_52_characters_of_lowercase_base32`.
- **Counts**: 731 tests pass with every feature (1 ignored, the 50,000-message scale test), 679 by default, 357 with `search` alone; clippy (`--all-features --all-targets -D warnings`), `cargo fmt --check`, `cargo doc` with `-D rustdoc::broken_intra_doc_links` and `-D missing_docs` clean.

## Departures

- `PimdirHash` is not a parsed type: the check is the blob store's at every path it builds (above). A consumer building a path itself calls `PimdirHash::is_name` or `PimdirBlobs::path`.
- The owner's reads inside a write transaction (the attachment walk, the summary of an overruled body, the capability gate inside the drain) read a failing body as missing and leave the move to the next owner read outside a transaction: the process's writer lock they hold is not reentrant, and the move must hold it exclusively.
- A body written under a name its bytes do not hash to (a `StoreObject` whose connector named it wrongly) is written as given; its first verified read finds it failing and the owner quarantines it. The write does not hash what it writes.
- A filesystem without hard links now fails every blob write, where a rename worked; STORAGE §5 allows `renameat2` with `RENAME_NOREPLACE` on Linux and `renamex_np` on macOS, which the crate does not use (the task asked for `hard_link`, which Windows maps to `CreateHardLinkW`).
- The quarantine move is a `rename` to a name checked free under the owner's locks, not a link: a link would follow a symbolic link on some platforms, and only the owner, holding both locks, moves into quarantine/.
- A `pimdir check` stray includes a writer's temporary, which a running writer may hold; STORAGE §5 has the collector report it, so check does too.
