# Store audit of 2026-10-30

The ledger of the release audit's store findings is closed: S1 and S4 landed earlier the same day, the rest here.

## What landed

- S5: the journal mode is set when the owner creates a store, and by no open of an existing one (src/client/schema.rs, src/client.rs `open_current`, src/client/producer.rs), so a store switched to a rollback journal for a network filesystem (STORAGE §8) stays on it; README says how. tests/store_rules.rs `a_store_on_a_rollback_journal_stays_on_it` (failed before: the producer set WAL).
- S6: README states the Annex A deviations (8-bit charsets read as UTF-8, `MIME_DEPTH_MAX`) beside cairn/spec/summaries.md, and claims storage-draft-05 and sync-draft-05.
- N8: a producer holds the staging lock for its staging window alone, from its first staged body until a committed enqueue pinned every one (kept until it drops after a streamed body), taken before the enqueue transaction. tests/staging.rs `an_idle_producer_keeps_no_collector_out` (failed before: refused beside an idle producer).
- N9: `purge_retained_before` refuses a cutoff not written as the stamps are, `PimdirError::Cutoff(String)` (`cutoff-invalid`). tests/retention.rs `a_purge_cutoff_not_written_as_the_stamps_are_is_refused` (failed before: `now` purged).
- N10 and N14 closed as unproven (cairn/changes/store-audit-2026-10-30/tasks.md has the reasons).
- Capabilities moved: store ("A producer stages its own body", "An error carries a stable code", modified; "The journal mode is chosen when the store is created", "A purge cutoff is written as the stamps are", added).
